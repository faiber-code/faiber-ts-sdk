Corrections prepared:

- Supply operation-specific query types so convenience signatures describe only consumed filters. Office lookup query is required. Report refresh retains period query on a bodyless POST.
- Document mutation idempotency keys, duplicate 409 behavior, optimistic locking differences, null-clearing behavior, legacy data scope exceptions, list ownership and cursor limits, creation status codes, and singular/plural route differences in every operation's reviewed JSDoc metadata.
- Replace README examples calling nonexistent `api.leads`/`markLeadDone` and incorrect PUT-only/bracket-pagination guidance with real methods, PATCH/version/idempotency workflow, scalar cursor pagination and actual transport behavior.

Backend source limitations are distinguished from SDK defects: all-node compatibility listing has no workspace predicate; legacy worklog repository has no workspace predicate; Office lookup has neither a local permission guard nor workspace predicate; history and board do not inherit lead ownership filtering; workflow version is accepted but not enforced. The SDK now describes these facts and does not claim to repair backend policy. Ordinary optional patch nulls preserve values; explicit nullable workflow/node fields clear values. JSON fields remain extensible only where Rust declares unstructured stored or remote JSON; the package README names these fields and why they are dynamic.
